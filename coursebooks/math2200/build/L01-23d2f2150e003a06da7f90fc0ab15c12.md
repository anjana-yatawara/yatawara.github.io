## What is R?

**R** is a free, open-source programming language built specifically for
statistics and data analysis. It was created by statisticians, for
statisticians, which is why — unlike a general-purpose language — it comes
with data analysis ideas baked in from the start: data frames (spreadsheet-like
tables), built-in statistical tests, and a huge ecosystem of add-on
**packages** (more in [L05](./L05.md)) written by the statistics community.

R is not a calculator app and not a menu-driven program like a spreadsheet.
You write short lines of **code** that say exactly what you want done, R does
it, and shows you the result. That extra step — writing the instructions down
— is exactly what makes an analysis **reproducible** (more below), and it is
the R skill this course grades (**CLO8**).

:::{note} Why this course uses R instead of a calculator or Excel
| | Calculator | Excel / spreadsheet | R |
|---|---|---|---|
| Free & open source | usually not | no (subscription) | **yes** |
| Handles a dataset with 1,000+ rows easily | no | slow, error-prone | **yes** |
| Every step is visible and re-runnable | no | hidden in clicks | **yes** |
| Used in industry data/analytics roles | rarely | somewhat | **widely** |
| Redo the whole analysis with one new dataset | start over | mostly start over | **re-run the same code** |

None of this means calculators or spreadsheets are bad tools — they are just
not built for what this course needs: repeatable, checkable statistical
analysis on real datasets.
:::

## What "reproducible" means

A data analysis is **reproducible** when someone else (including *future
you*, a week from now) can run the same code on the same data and get the
**exact same answer** — not a similar answer, the exact same numbers, plots,
and conclusions.

Three ingredients make an R analysis reproducible:

1. **The code** — every step written down, in order, as a script or notebook
   (not clicks you can't retrace).
2. **The data** — a specific file or dataset, not "whatever was in my
   spreadsheet that day."
3. **The random seed** — if any step involves randomness (and several methods
   in this course do — see [L08](./L08.md) and [L09](./L09.md)), the *starting
   point* of that randomness has to be fixed, or "random" results will be
   different every time you run the code.

That third ingredient is the one that surprises people, so let's see it in
action.

## Demonstration: why `set.seed()` matters

R can simulate randomness — for example, "roll a fair six-sided die" — with
`sample()`:

```r
sample(1:6, size = 1)
```
```
[1] 1
```

Run that exact same line again, with nothing else changed:

```r
sample(1:6, size = 1)
```
```
[1] 5
```

Different number. That's expected — it's a random roll — but it means if you
handed this code to a classmate, they could not check their answer against
yours, and you could not check your own answer a second time. For homework,
labs, and answer keys, that's a problem.

The fix is `set.seed()`. It tells R exactly where to start its "randomness,"
so the sequence of "random" numbers that follows is **the same every time**:

```r
set.seed(2200)
sample(1:6, size = 1)
```
```
[1] 4
```

Now reset the seed to the same value and roll again:

```r
set.seed(2200)
sample(1:6, size = 1)
```
```
[1] 4
```

Same seed, same starting point, same "random" result — every time, on every
computer, forever. That is what makes a simulation-based method (which this
course uses heavily) gradable: your instructor's answer key was produced with
a fixed seed, so it can be checked exactly.

:::{important} The rule for this whole course
**Every time your code involves randomness, run `set.seed(2200)` immediately
before it.** `2200` is simply this course's chosen seed value — any fixed
number works the same way, but using the same one as your instructor means
your simulation results will match the key. You will see this pattern in
nearly every code example from [L08](./L08.md) onward.
:::

## A first taste: R computing a real number from real data

R ships with some datasets built in, and this course adds the `mosaic`
package (introduced fully in [L05](./L05.md)), which supplies a very readable
way to ask for summaries. Here is the average length, in minutes, of an
eruption of Old Faithful geyser — a real, famous dataset that ships with R
itself:

```r
set.seed(2200)
mean(~ eruptions, data = faithful)
```
```
[1] 3.487783
```

You will not fully understand the `~ eruptions` syntax yet — that is
[L05](./L05.md)'s job — but notice what just happened: real code ran on a
real, documented dataset (`?faithful` in R tells you its source) and produced
a real number, printed right here. Every number in this book, and in every
lesson that follows, is produced exactly this way.

## Summary

- R is a free, open-source language built for statistics; MATH 2200 grades R
  as a real skill (CLO8), not an accessory.
- A **reproducible** analysis needs fixed code, fixed data, and — whenever
  randomness is involved — a fixed seed (`set.seed()`).
- `set.seed(2200)` before any random step is this course's standing rule.
- Every number, table, and plot in this book was produced by R code you can
  see, run, and check yourself.
